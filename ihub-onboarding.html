much. Integration Hub — onboarding

How iHub connects Odoo to external systems, with real examples from the Shopware integration.

1. The big picture

iHub is a standardized middle layer. Instead of every connector being a bespoke build, they all reuse the same seven building blocks. In code, an integration is two linked records: the shared ihub.integration (the super_id) plus a connector-specific model (the sub_id).

2. The three-level stack

For shops, the layering is real: the Shopware connector only knows how to talk to Shopware's API; it plugs into order base, which owns the generic shop logic; which plugs into iHub. Order base calls a generic import_orders() and iHub's handler pattern routes it to import_orders_shopware_shop() — so swapping Shopware for Shopify changes only the top layer.

3. The workflows

Start with the one-time setup, then the six live workflows. The teaching point across all of them: the same iHub blocks appear in different combinations — only product import leans on the queue, only heavy syncs spin up a job, but every workflow logs and every cron can be watched.
