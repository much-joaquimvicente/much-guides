Onboarding a DATEV API Customer

The exact steps to provision a customer who subscribed to the DATEV API integration — from their ticket to a working “Get Access Token” button in their Odoo.

much. GmbH · Odoo 19 · DATEVconnect (native API) · internal use only
🧠 The one big idea

Two authorizations must line up — always both. (1) A subscription key we mint in the DCS (DATEV Credential Service) and email to the customer, and (2) a redirect URL we register in the DATEV developer portal so DATEV is allowed to hand the token back to their instance. Miss either one and “Get Access Token” fails.

0 What you need before you start

This is an internal provisioning job done by much. technical support. Gather these first.

  • Access to the DCS (DATEV Credential Service) — dcs.muchconsulting.dev. This is the internal site where we register every customer and where the subscription keys are minted.
  • Access to the DATEV developer portal — the much. – Odoo Connector app: developer.datev.de → much. – Odoo Connector.
  • The customer's product ticket with their Odoo instance URL(s).
🔒

Hands off the app credentials. In the DCS, the “API Credential Services” section holds the data-app's own DATEV credentials. Never modify it — it only ever matters if the data app is recreated. Your job is creating clients, which is a separate thing you do all day long.

1 The ticket — where the URLs come from

Customers (or their consultant) request the integration through the product-ticket form.

They open erp.muchconsulting.de/open-product-ticket and choose type “DATEV API integration”. The form's URL fields correspond to the customer's Odoo instances — typically a QA/staging URL, a release URL and a production URL (two testing, one main).

When the ticket lands, all you take from it is the URLs. And from each URL you only need the base domain — everything before the path (/odoo, /web, query strings, etc.).

Ticket says: https://acme-prod.odoo.com/odoo/action-123/... You keep: https://acme-prod.odoo.com
💡

One customer usually has several instances (QA, staging/release, production). Run the two steps below once per URL.

2 For each URL — do both steps

Step A mints and emails the subscription key. Step B lets DATEV send the token back into that instance. Both are mandatory.

A · Register the client in the DCS (mint & email the key)

1

Open the DCS → “Add New API Client”

Go to dcs.muchconsulting.dev. Creating a client automatically creates a 1Password entry and shares it to the email you provide.

2

Fill the form and click Add Client

  • Name — a display name for this client.
  • URL — the base instance domain (the origin that will access the DATEV credentials). Must be https — the form validates it.
  • Email — the contact who opened the ticket. This is where the subscription key is sent, so double-check it.
  • Subscription Valid Until — set roughly one year out. Leave empty for unlimited. If the subscription is renewed later, come back and bump the date.
3

The key is emailed automatically

On save, the DCS emails the customer their API subscription key. That key is what unlocks the “Get Access Token” button inside their Odoo DATEV settings.

📧

Entered the wrong email? Just edit the email and save — the DCS re-sends the key to the corrected address. Confirm the customer actually received it.

B · Register the redirect URL in the DATEV portal

1

Open the much. – Odoo Connector app in edit mode

Open developer.datev.de → much. – Odoo Connector → Details. Then click the ⋯ (three dots) at the top-right of the app form and choose “Edit App” — now the Redirect-URI(s) list is editable.

2

Add the callback URL

Add the same base instance domain with /datev/oauth/callback appended, and Save:

https://acme-prod.odoo.com/datev/oauth/callback

This “call back” is what lets DATEV authenticate back to Odoo and save the token in the instance. Without it, the OAuth window has nowhere to return the token.

⚠️

Be careful in the portal. Edit and Delete sit right next to each other — do not delete the app. Only add your new redirect URL; never touch the existing entries or the app credentials.

3 Hand-off — what the customer does next

Once both registrations are done, the rest happens on the customer's side in Odoo.

1

Paste the subscription key

In Odoo → Accounting → Settings → DATEV (API integration), they paste the subscription key they received by email.

2

Click “Get Access Token”

The DATEV OAuth window opens — allowed only because the redirect URL is registered — they log in / grant permissions, and the token turns green (valid).

3

Click “Enable Integration”

From here the scheduled export data cron sends the Buchungsstapel, master data and PDFs to DATEV on the frequency they chose (daily or monthly).

🔁

The green token proves the two-step setup worked end to end: the key (from your DCS client) authenticated them, and the redirect URL (from the portal) let DATEV return the token to their instance.

4 Troubleshooting & reference

The failures you'll actually see, and where each piece lives.

SymptomMost likely causeFix
“Could not get access token” / OAuth errorClient not subscribed, or user lacks rightsConfirm the DCS client exists and the subscription is still valid; confirm the customer's DATEV user has access to the needed services.
OAuth window won't return / redirect mismatchRedirect URL doesn't match the instanceThe portal redirect URI must equal the instance base domain + /datev/oauth/callback exactly — https, no typo, no extra path.
Key “not recognised” in settingsWrong/partial key pasted, or wrong instanceRe-check the emailed subscription key was pasted into the right instance's settings.

Under the hood — the moving parts

PieceWhat it is
DCS (DATEV Credential Service)Internal registry at dcs.muchconsulting.dev where we register all customers and send subscription keys. Clients are created here; the app-credential section is never touched.
much. – Odoo Connector appThe DATEV-side app (a.k.a. the “merge Odoo connector” / master application) the customers subscribe to. It exposes endpoints for Check clients (rights), Documents (PDFs) and Ext files (the export file).
Redirect URIThe /datev/oauth/callback route on the customer's instance, registered in the portal so DATEV may return the OAuth token.
