👋 Welcome — start here

This handbook builds on the Odoo Accounting & Invoicing handbook. If invoices, journal entries, debits/credits and reconciliation are still fuzzy, read that one first — everything here assumes you know what a journal entry is.

Here we cover the piece that's specific to Germany and to us: getting Odoo's accounting data into DATEV, the software our clients' tax advisors (Steuerberater) use. These are the much. DATEV modules our team builds and maintains.

🧠 The one big idea

In Germany, the Steuerberater (tax advisor) does the official books in DATEV. Odoo is where the business actually works day-to-day. So Odoo needs to hand its bookings over to DATEV in DATEV's exact format. That handover is the only thing these modules do — three ways: download a file, import a file, or push automatically over the DATEV API.

1 What is DATEV?

The accounting standard at the heart of German bookkeeping.

DATEV is a large German cooperative that makes the accounting and tax software used by almost every German Steuerberater (tax advisor) and many companies. When a German business keeps its books, the numbers almost always end up in DATEV so the tax advisor can review them, file taxes, and prepare the annual accounts.

A typical setup: the company runs Odoo (sales, invoices, bills, bank), and its tax advisor runs DATEV. Every month the company's bookings must travel from Odoo to DATEV. Historically that meant printing lists or copying files by hand. Our modules automate it.

🏢 In Odoo

The business records invoices, bills, payments and bank entries — the daily work.

🧑‍💼 In DATEV

The Steuerberater reviews the bookings, files VAT, and prepares official year-end accounts.

ℹ️

Why not just use one system? German tax advisors are deeply standardised on DATEV, and the law/audit trail lives there. So the practical answer is: keep working in Odoo, but speak DATEV's language when handing data over.

4 Configuration

Set up once per client. Get these right and exports "just work"; get them wrong and DATEV rejects the file.

Step 1 — Consultant & Client numbers (required!)

The Consultant Number (Berater-Nr.) and Client Number (Mandanten-Nr.) live on the Company (standard German-localization fields, not our custom tab). Every export refuses to run without them — you'll see: "Please configure the DATEV consultant number and client number in the company form settings."

Settings → Users & Companies → Companies → (your company) → DATEV fields

Step 2 — The "DATEV Export" settings tab

Everything else is on our tab:

Receivable Format (default 10000)Starting number for auto-assigned Debitor (customer) accounts — DATEV convention.

⚠️

SKR03 vs SKR04 is chosen when the company is set up (via Odoo's German localization) — there's no separate selector in our tab. Length General Accounts must match that chart, or account numbers won't line up in DATEV.

5 Debitor & Kreditor (Customer/Vendor numbers)

DATEV doesn't book against "the customer" — it books against a numbered sub-account. Each customer and vendor needs a DATEV number.

⬇️ Debitor = Customer

Field DATEV Customer Identifier. Auto-assigned from the Receivable Format range (10000, 10001…).

⬆️ Kreditor = Vendor

Field DATEV Supplier Identifier. Auto-assigned from the Payable Format range (70000, 70001…).

On any customer/vendor you'll find these fields (under the Set DATEV Identifier permission). Leave a number blank and the system assigns the next free one automatically; or paste an existing DATEV number to keep continuity with what the Steuerberater already uses. Numbers must be unique.

Actions on a partner

  • Generate Customer Identifier / Generate Supplier Identifier — assign a number now.
  • Download DATEV CSV — export just this partner's master-data record.
  • Exported to DATEV / DATEV Export Date — read-only status. A DATEV Update Required flag re-includes the partner in the next export whenever a watched field (name, address, VAT, bank, receivable/payable account…) changes — so master data in DATEV stays current.
🔁

This is what the SDD Change Tracking module extends: change a customer's SEPA mandate and it automatically flags them for re-export, so DATEV always has the latest bank/mandate details.

6 Export: Buchungsstapel (CSV)

The workhorse. Turn Odoo's posted bookings into a DATEV booking batch the Steuerberater can import.

What's exported: your posted journal entries — customer invoices, credit notes, vendor bills, refunds, and bank/cash/general entries — as a DATEV Buchungsstapel CSV. The first row is the EXTF header (firm, client, fiscal-year start, account length, date range); the rest are the bookings.

How to export — two entry points

AOn an invoice/journal-entry list: select records → Actions → Download DATEV File.
BOn the General Ledger report (DE companies): the Download DATEV File button, using the report's date filter.

Both open the Download DATEV Format chooser with three formats:

FormatYou get
CSVThe plain Buchungsstapel. If new customers/vendors are involved, a ZIP with the bookings file (EXTF_accounting_entries.csv) + the partner master file (EXTF_customer_accounts.csv).
CSV + PDF (ZIP)The CSV(s) plus each invoice's PDF and a document.xml that links every PDF to its booking (Chapter 7).
XMLRoutes to the XML export (Chapter 8).

What happens to customers & vendors (Debitor/Kreditor)

On receivable/payable lines, the module swaps Odoo's account for the partner's DATEV sub-account number. Debit shows as S (Soll), credit as H (Haben). If a partner has no number yet, one is created from the configured range and saved on the partner.

📦

Big date ranges? The General Ledger export shows a batch selector ("Move X to Y") with a Next Batch button, honouring your G/L Export Batch Size. A Missing DATEV Account filter helps you catch entries with no account set before exporting.

7 Export: CSV + PDF & Download Bills

Send the bookings and the source documents, so DATEV shows the invoice PDF next to each booking.

CSV + PDF (ZIP)

Same as the CSV export, but the ZIP also contains every invoice's PDF plus a document.xml manifest. That manifest is the Beleglink (BEDI) — it tells DATEV which PDF belongs to which booking, so the Steuerberater sees the original document right beside the entry. This is the format clients love, because it removes all the "where's the invoice for this line?" back-and-forth.

Download Bills (.zip) — PDFs only

A simpler tool (from the Base module): select invoices → Actions → Download Bills (.zip) to get just the PDFs, named Bulk_Invoices_<timestamp>.zip — no CSV. Handy when someone only needs the documents. A daily clean-up cron removes these temporary zips automatically.

💡

Each invoice remembers its DATEV Export Date and Zip Export Date, so you can always see what's already been sent.

8 Export: XML (Belegverwaltung online)

A structured, per-invoice data record that lets DATEV book the invoice automatically — no manual typing on the DATEV side.

Where the CSV is a batch of bookings, the XML export produces one DATEV XML record per invoice/bill (schema Belegverwaltung online). It's not a scan — it carries the structured data: amounts, tax, invoice/due/delivery dates, invoice number, the partner's DATEV number, order reference, VAT IDs and bank details. DATEV reads it and proposes the booking automatically.

How to export

1Only posted invoices, credit notes, bills or refunds qualify.
2Select them → Actions → Download DATEV File → XML.
3One record → a single .xml; several → a .zip of one XML each. Each XML is also attached to its invoice and noted in the chatter.

Invoices then show read-only Exported as XML and XML Export Date fields, with matching search filters so you can track what's been sent.

ℹ️

Each XML carries the standard DATEV note "Kopie nur zur Verbuchung berechtigt nicht zum Vorsteuerabzug" — a legal disclaimer that this copy is for booking only, not for reclaiming input VAT.

9 Import from DATEV

The reverse direction — bring DATEV booking files back into Odoo as draft entries (e.g. bookings the Steuerberater made, or historical data).

How to import

Accounting → Import DATEV CSV

The Import DATEV wizard asks for:

  • Counter-Account — whether the counter account is in the Konto or Gegenkonto column.
  • Import Journal — the target journal (must be flagged Is DATEV Import Journal?).
  • Year and Is Legacy Data Imported? — for historical/opening-balance data.
  • Files — one or more DATEV EXTF CSVs. One calendar month per file (multi-month files are rejected).

Each grouped set of rows becomes a draft journal entry — left in draft so you review before posting.

⚠️

Import matches, it does not create master data. Accounts (Sachkonten), taxes (via BU-Schlüssel), currencies and analytic accounts must already exist — a missing one aborts the import. Only a missing partner is tolerated (it falls back to the journal's default receivable/payable account and logs a warning). It does not import a chart of accounts.

Checking what happened

Open Accounting → DATEV Import Logs (read-only, newest first). Each log has a Level — Info (blue) or Data Issue (amber) — and details. After a run you get either "import success" or "completed with warnings"; filter by Level = Data Issue to see problems like "The partner does not exist."

10 DATEV API (DATEVconnect)

The premium option: skip files entirely. Odoo talks straight to the DATEV cloud and pushes bookings, master data and PDFs automatically, on a schedule.

One-line pitch: post an invoice in Odoo and it appears in DATEV by itself, with the PDF attached — and you're emailed if anything fails.

Connecting (one-time OAuth)

1On the DATEV Integration record, click Get Access Token.
2Odoo opens DATEV's own login page — the user signs in with their DATEV credentials and authorizes the scopes.
3DATEV redirects back; Odoo stores the tokens. Buttons then become Refresh / Revoke. Thanks to the offline_access scope, the connection lasts ~2 years.
🔒

The user logs in on DATEV's page — we never handle their DATEV password, and the OAuth client secret is fetched automatically (the accountant never types it). Use Is Sandbox Mode? to test safely before going live.

Export settings

  • Export Frequency — Daily / Monthly / Quarterly.
  • Journals to Export, Export Start Date.
  • Data to Export — toggles for master data / accounting entries / PDF documents.
  • PDF Export — Optional or Mandatory (with a size limit).
  • Category / Folder / Register — where files land in DATEV.

Running & monitoring

Manual push: select records → Actions → Export to DATEV API, or on the integration record Export via API (with an Include Already Exported? option and a duplicate warning). Automatic push: the DATEV: Export Data cron runs on your chosen frequency.

Track everything in DATEV Export Jobs (read-only): each batch shows a Status (Created → Started → Success / Failed / Cancelled), the last step, the DATEV job id, retry count, and a Logs button. Failed jobs have a Retry Job button. If something breaks (expired token, failed export), admins get a grouped "Critical Error in DATEV Integration" email with a link straight to the logs.

💡

File vs API — how to choose: use CSV/XML file export when the Steuerberater wants to import files themselves; use the API when the client wants true hands-off, automatic syncing.

★ DATEV Glossary

German bookkeeping terms, decoded.

DATEV
The German cooperative whose software tax advisors use for accounting and tax filing.
Steuerberater
A German tax advisor — the professional who keeps the official books in DATEV.
EXTF
DATEV's import/export file format. The first CSV line (the "EXTF header") identifies firm, client, period and file type.
Buchungsstapel
A batch of bookings — the accounting-entry CSV. = Odoo's posted journal entries.
Berater-Nr. (Consultant Number)
Identifies the tax firm. Set on the Odoo Company; exports fail without it.
Mandant-Nr. (Client Number)
Identifies this specific client's file in DATEV. Set on the Company.
SKR03 / SKR04
The two standard German charts of accounts. Chosen at company setup.
Sachkonto
A general-ledger account (a "Konto"). Gegenkonto = the counter/contra account on a booking.
Debitor
A customer sub-account (DATEV range 10000+). = Odoo customer + DATEV Customer Identifier.
Kreditor
A vendor sub-account (DATEV range 70000+). = Odoo vendor + DATEV Supplier Identifier.
Soll / Haben
Debit / Credit — written as S / H in the file.
BU-Schlüssel (Buchungsschlüssel)
DATEV tax/booking key. Maps to Odoo taxes; the default key 40 switches off DATEV's auto-tax on a line.
Belegfeld 1 / 2, Belegdatum, Buchungstext
The document reference, dates and posting text on each booking row.
Beleg / Belegverwaltung online
Documents (invoice PDFs) and DATEV's online receipt management — fed by the XML export and the API's PDF push.
Beleglink (BEDI)
The link that ties a PDF to its booking (the document.xml in a CSV+PDF zip).
KOST1 / KOST2 (Kostenstelle)
DATEV cost centres. Map to Odoo analytic plans.
DATEVconnect
DATEV's cloud API — what our API Integration module connects to for automatic syncing.
